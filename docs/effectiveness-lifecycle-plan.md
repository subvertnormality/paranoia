# Effectiveness pilot and typed class lifecycle

This card addresses GitHub issues 49 and 50. The preceding batching campaign is historical and unchanged.

## Operating model
One trusted local operator and OS run Paranoia and signed-in Codex/Claude CLIs. Repository, plan and provider bytes are untrusted static data. Reviewers do not execute repository-selected code. Ordinary edits invalidate bindings and block/retry. Three census lanes may run concurrently; pilot trials run sequentially. Network uses existing provider CLIs only; the pilot makes no external claims and disables web research. Fixtures contain tens to hundreds of lines; normal repositories contain hundreds to thousands of files and tens to low hundreds of claims. Evidence should be useful within minutes. False clear, authority errors and wrong evidence binding have high impact; recoverable blocking is acceptable. Exclude hostile same-user races, compromised OS, multi-tenancy, corrupted-state recovery, formal proof and population performance guarantees.

## Binding PLAN clarifications

B1 (blinding and topology). M3 is the sole topology authority. Q2's concealment
applies to oracle answers, sibling control bytes, historical fix metadata,
experimental arm labels and cross-slot/comparator results. Native query/census/
consolidation/final identities and mandatory within-slot manifests, debt and
concessions remain visible and unchanged. This is information withholding under
the frozen trusted-operator model, not an OS sandbox against a hostile reviewer.
Both arms see an independently initialized repository whose base contains only
the common specification and an empty app.py, and whose head introduces that slot's
app.py and context helpers. No correct implementation is placed in a defective
slot's history. Fix commit metadata and original provenance exist only in the
oracle. Freeze base/head file maps, constant author/time/message metadata, complete
two-commit history, tree IDs and generated branch packet hashes. Both query and
branch provider callbacks inspect the actual cwd files, history and prompts before
calling the underlying engine. They reject unexpected bytes/history or oracle/
sibling markers before spend. Tests use both defective and corrected public-handler
paths, including a deliberately contaminated base. Each Q2 case has one fixed
provider; its paired control uses that same provider. Schedule cardinality is
derived only from Q2's cases, arms and repetitions, never a second hard-coded loop.

B2 (scoring authority). scripts/score_effectiveness.py owns the following scoring
contract; freeze its bytes and this contract before first spend. Implementer rows
for both arms are exact quoted output spans with a reason and an ordinal,
classified blocking-actionable, advisory, or non-finding. Staged rows identify
native governing findings, not every lane's intermediate observation; repeated
governing IDs across rounds count once. Query recommendations are blocking only
when their text asserts a contract defect requiring correction; optional advice
is advisory. Preserve all extracted rows and require an explicit coverage
attestation that no actionable assertion was omitted from either format.
Match each actionable finding to the exact seeded/historical oracle witness by
concrete trigger, violated invariant and location, never keywords alone. Duplicate
reports of the same defect cluster count once for precision and recall; retain
every duplicate quotation. One matching cluster is TP; a disproved contract-defect
assertion is FP. Unexpected valid defects require a separately recorded executable
witness and fixture-problem classification; never automatically call them FP.
Uncertain matches, omitted annotations and fixture problems are unscored and block
comparative qualification, retaining all observations. Oracle fixtures contain
one target defect or zero in the corrected control.
Finding precision is TP/(TP+FP); target-defect recall is detected oracle defects/
all scheduled defective slots. Case false-clear and false-positive rates use all
scheduled defective and clean slots respectively; unresolved/failed slots remain
in denominators and are reported separately, never silently credited as clear.
A clear needs explicit no-actionable-defect output and successful execution;
staged clear additionally requires durable phase clear and its native computed
NOT-BLOCKED trailer. A detected target can count as detection before staged
convergence, but cannot count as a clean result. Zero denominators produce null
with an explanation, never 0 or 1; undefined required precision/recall withholds
superiority. Report both all-slot totals and matched successfully adjudicated
pair timing, with the latter's selection limitation. Include min/median/max and
range for two-repeat timing, plus exact counts rather than spurious tight
confidence estimates. Unit tests cover both output formats, duplicates, advisory,
unexpected defects, empty output, controls, failures and ambiguous matching.

B3 (custody authority). scripts/benchmark_effectiveness.py:qualify_campaign is
the single runner/scorer/replay gate. Its closed frozen manifest joins each exact
scheduled slot to configuration, source_record, harness/bootstrap/scorer hashes,
fixture snapshot/packet and oracle digest. Worker input is projected from that
manifest; callers cannot override it. Shared validate_source, validate_harness,
install_observer, validate_channels and require_successful_review retain their
existing authority. Check source and fixture bytes before import/dispatch and
after dispatch, including query ordinary edits. Join every observed attempt to
its native audit via prompt/raw/session/engine as appropriate; require actual
engine/model/effort/settings, successful Review channels and return code for
semantic credit. Retain invocation failures distinctly even without a Review.
Bind exact returned text, native audit bytes, attempt/channel files, durable
staged state and scorer rows in terminal custody metadata; report replay
revalidates files and execution rather than trusting a prior score or boolean.
Require unique slots and attempt sequences and reconcile the complete admission
counter, including failed attempts, with no unaccounted admissions. Run-time
admission uses the Q3 ceiling. A rejected or exhausted slot retains its original
terminal record, attempts, known costs and rejection, without semantic credit.
Qualify only the complete frozen schedule with intact custody; any custody
mismatch blocks delivery rather than producing a partial qualified report.
Deterministic negatives cover changed fixtures/source/channels, swapped/missing
output or audit, duplicate/missing slots or attempts, exhausted admission,
failed dispatch, failed Reviews with plausible findings, and census-only clear.
Q3/Q4/Q6 and Delivery refer to this gate; report generation cannot bypass it.
Honest operational outcomes with intact custody are reportable measurement
failures, not custody corruption; they cannot receive semantic success credit.

B4 (human handoff). The operator Andy owns independent human acceptance under
issue 49. The packet presents specification, reviewed code and exact review text
with only the deterministic native footer removed, in a frozen shuffled order.
This is oracle/annotation withholding, not guaranteed arm/provider-blinded human
adjudication: native wording, trailers and diagnostics may reveal workflow/provider
identity. Preserve those cues and all failure meaning instead of claiming to redact
them. Exported metadata contains no harness arm/provider labels or implementer
scores. The packet prominently states this limitation.
Each item has an opaque ID and content digest; a separate withheld map binds it
to its slot. For every item ask whether the review is accurate and actionable:
accept, reject, or uncertain, with a short reason and any incorrect assertion.
A complete rating file must bind the exact packet digest and every item exactly
once. Aggregate accepted/rejected/uncertain counts and acceptance rate; incomplete
or absent ratings remain pending. Human acceptance is complete only when all items
are rated, and the pilot's human-acceptance criterion is at least 90% accept with
no accepted false-clear report under the oracle. Record disagreement rather than
changing the oracle or implementer score retrospectively. Packet export and
rating validation are owned by score_effectiveness.py and tested for missing,
duplicate and stale-digest ratings. This card can merge a fully qualified
measurement with human ratings pending; issue 49 remains the explicit durable
owner of that residual and cannot be claimed resolved until it is completed.

B5. Human export tests cover normal output, provider-named failure prefixes,
recovered-validation diagnostics and staged failure bodies. All original native
text except the exact standard footer must remain byte-identical; verify its
projection against custody-bound source output and retain native cues with the

interpret the preserved native cues as a failed concealment guarantee: B4 does
not make that guarantee. This narrower reporting contract requires no production
