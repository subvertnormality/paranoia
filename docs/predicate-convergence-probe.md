# Bounded predicate-convergence investigation

## Operating model
One trusted local operator and OS. Original fixture, plan, repository and provider bytes are static untrusted data; reviewers read but never execute repository-selected code. The implementing agent may execute the explicitly authorized fixture calibration in isolation. No hostile local races, OS compromise, multi-tenancy, corrupted-state recovery, web research or formal proof. Ordinary edits invalidate bindings. Existing provider CLI network boundary; one local JSON-compatible input consumer, no function concurrency. A few files and one blocking class; evidence useful within minutes. False clear, wrong binding and authority errors are high impact; recoverable blocking is acceptable.

## Procedure and stop rules
P1. This is an investigation, not a production implementation or new full corpus campaign. Keep all production files, prompts, roles, schemas, normal timeout caps and the accepted optimization gate unchanged. Work in an isolated directory; never modify the sealed calibrated campaign or its scores, state, repositories or receipts.
P2. Freeze the original t029 input, repository commits, lineage state and native audit hashes. Copy its repository and exact round-1 lineage bytes into an isolated continuation with the same lineage ID in a different state root. Do not rewrite class/debt IDs, invariants, predicates, stakes, sessions or round labels. Disclose this as a seeded continuation, not a fresh independent census. Verify current production bytes and CLI versions match the original run.
P3. Make exactly the previously demonstrated in-domain Boolean-guard repair in the copied app.py: prepend isinstance(index, bool) to the existing rejection condition. Commit it; leave specification/helpers unchanged. Require successful calibrate("identity", files_from_the_committed_repair, False), exactly the existing 100 check IDs, no failed observations, and exact file bindings. Retain the observations and diff before provider admission. Any exception, incomplete result, failed check or binding mismatch stops before P4. Retain the original witness and the fact that the historical predicate still matches this valid repair. No new acceptance corpus or general harness.
P4. Invoke the existing server.dispatch critique_branch handler at round 2 with the inherited base, new committed head, exact original stakes, provider/model/effort/web settings and copied lineage. Do not supply a new plan contract to this previously contract-free lineage, caller class edits, exemptions, focus nudges or special repair advice. The existing handler chooses its normal correction route.
P5. If and only if native state advances to final, invoke its ordinary required cold final at round 3 on the same snapshot. Otherwise stop and preserve the blocking/failure result. At most these two review invocations and four provider calls including existing validation retries. P1 governs timeout caps. No selective rerun, extra repair, forced state transition, new census, second live arm or production modification.
P6. The isolated probe.py uses qualify_continuation with existing effectiveness_custody.collect_slot, install_checks, validate_channels and source validation; its preflight binds seed bytes, production/harness bytes, committed base/head/trees/history/files, calibration and exact requests. It requires positive original-custody acceptance and negative controls for changed head, altered channel, missing native audit and duplicate attempt before spend. Qualification joins each output and its digest to a unique native run, role/attempt ledger, execution settings, source observations, raw channels and durable lineage; post-correction qualification gates final admission, and final qualification gates reporting. Any mismatch stops further calls and withholds success credit while retaining costs. Use the existing call observer to retain actual elapsed dispatch/call time, attempts, usage and raw channels with native audits, state before/after and exact request/output bindings. Freeze invocation inputs and source before calls, validate afterward, and recheck the sealed seed bytes unchanged. Failed, refused and unresolved results retain costs and earn no success credit. Include setup/calibration time separately; no subtraction of failed work.
P7. Report whether correction and final actually completed, class/debt outcomes, any code/style demand, and measured total time/calls. A single seeded trajectory does not establish population performance or causality versus a live counterfactual; no percentage speedup claim from this probe. Evaluate the smallest potential remedy from the observed mechanism, without implementing it here. Stop if evidence fails to support credible 20% end-to-end time/cost improvement with neither materially worse, or substantial maintenance simplification at high confidence.
P8. This bounded investigation has one design check before the probe. Production implementation requires a separate warranted design and CODE acceptance. Corpus redesign and another 32-slot campaign remain deferred. Preserve the accepted quality gate; do not declare issue 49 or 50 resolved.
