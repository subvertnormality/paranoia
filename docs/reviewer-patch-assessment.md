## Frozen operating model

The deployment is the existing single-user local MCP server and supported local reviewer
CLIs. The operator, OS, Git executable, and server implementation are trusted. Repository,
plan, fetched, and model-produced bytes are untrusted static data. The proposal role may
read a pinned workspace and transform text in memory; it may not write repository files,
execute repository-selected programs, run tests, install packages, or browse. There is no
hostile same-user path race, compromised OS, multi-tenancy, or deliberately corrupted-state
recovery. Existing census lanes retain their ordinary concurrency; proposal continuation is
serial. Expected scale is tens to low hundreds of findings and minutes of latency. A false
clearance, wrong authority, or wrong snapshot binding is high impact; a recoverable refusal
or missing patch is acceptable. Formal proof and excluded hardening are not acceptance goals.

## A4 — continuation capability probe

`scripts/probe_patch_proposal_feasibility.py` uses the production staged prompt, provider
schema projection, local lane validator, native engine route, and a successful fresh-census
session. It resumes that session with a distinct closed proposal schema, validates exact
preimages, and records both attempts and channels. It never applies a proposal or runs tests.

After explicit egress approval, both engines successfully used fresh staged structured output
and adopted the proposal schema on the retained successful session. Codex proposal argv has
exactly one literal `sandbox_mode="read-only"`, disables web and interactive capabilities,
and has no writable roots. Claude uses safe mode, empty setting sources, strict MCP config,
and only `Read,Grep,Glob`; web is disabled.

The structural plan cases qualified on their first proposal attempts (83.248 s Codex,
95.902 s Claude total). Claude's verified case qualified in 203.267 s after five claim
attempts, one lane attempt, and one proposal attempt. Codex P2 completed its current claim
audit with two blockers, then hit the obsolete one-blocker harness assertion before a lane or
proposal call; exact attempt costs were lost and are marked unavailable. A4 is **COMPLETE**,
including retained negative evidence.

## A5 — feasibility decision

**GO for production implementation, not for the default flip.** Both native routes produced
usable snapshot-bound proposals; both structural plan routes qualified; the architectural
case remained an honest decline; and neither route required write permission, web, or
repository execution. Originating sessions and lane attempts remain distinct from proposal
attempts. The repeated-occurrence failure is a quality warning, and P2 is a harness-retention
warning, but neither negates the continuation/schema capability A5 tests. They remain inputs
to the later controlled and human gates. `PROPOSE_PATCH_DEFAULT` stays false until G1-G6 pass.

## Cost hypothesis and conclusion

Potentially avoidable work is caller source rediscovery and translation of findings into exact
edits. The repeated-occurrence failure shows sibling coverage is not inherently avoided.
Unavoidable work includes original review, proposal call, caller inspection, application or
amendment, tests, tracked correction, and cold final. Proposal inference added 8.3-26.5 seconds
in retained qualifying examples; full runs took 47.2-203.3 seconds, with the verified case
dominated by claim work. Subscription price and human time remain unknown. This small
convenience sample establishes feasibility only, not speed, cost, correctness, or
maintainability benefit; those claims remain for the controlled and human gates.
