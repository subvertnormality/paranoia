# Behavioral class authoring and bounded performance investigation

## Frozen operating model
One trusted local operator and OS run the MCP server and authenticated reviewer CLIs.
Repository, plan and provider bytes are untrusted static data. Reviewers inspect but do
not execute repository-selected code; the implementing agent may run the authorized
isolated calibration/tests. Ordinary edits invalidate bindings. Existing provider CLI
network boundary; no external factual claims or web research in this card. Three parallel
census lanes and sequential consolidation/correction/final; small fixtures through
thousands of files, tens to low hundreds of claims, evidence useful within minutes.
False clearance, wrong evidence binding and incorrect blocking authority have high
impact; recoverable blocking is acceptable. Exclude hostile races, compromised OS,
multi-tenancy, corrupted-state recovery and formal proof. The operating contract preserves
all existing reviewer roles/calls, cold independence, native retries and timeout caps;
later sections refer to this authority rather than redefine it.

## Scope and acceptance
Q1. Establish one shared class-authoring instruction: derive the invariant from the
governing requirement within the supported domain; separate suggested repair syntax;
accept compliant alternatives unless the actual requirement mandates a representation.
A mechanized predicate must match violations only, including against compliant alternative
repairs; otherwise use the existing unmechanized procedure and complete member inventory.
Do not add keyword lints, semantic-proof claims or weaker validation; preserve the
operating contract.

Q2. Apply guidance to staged consolidation/correction/final in both plan and branch modes
and legacy registration. Preserve the operating contract, manifest-only consolidation, evidence,
member checks, severity authority and canonical settlement. Existing class definitions,
mechanized replacement/sweep authority, debt, concessions, wire/state and persistence
remain unchanged. The historical trapped lineage is evidence, not a migration target.
Genuine governing syntax requirements remain enforceable.

Q3. Focused production-handler regressions: original Boolean-as-integer defect blocks;
both exact-type and Boolean-exclusion repairs reach correction then cold final under a
faithful behavioral class; missing member/evidence and still-defective repairs block.
Prove shared guidance reaches initial and native retry authoring paths without overriding
existing mechanized authority. Run the relevant tests, full suite and existing staged
protocol mutation checks; do not invent a second acceptance engine.

Q4. Live acceptance reuses isolated identity calibration and existing custody primitives.
Bind source/CLI/input/snapshot/provider channels/native audits/lineage. Fresh candidate
census per provider (Codex and Claude) sees the original defect without oracle or repair
hints. Copy each exact authored state/repository into two disclosed continuation arms for
the two calibrated repairs. These share one census per provider; they are not independent
samples. Each correction invokes ordinary cold final only after qualified native advance
to final. Require original-defect detection and both repairs durably clear for both
providers without unsupported blockers. Retain all failures/costs; no selective rerun,
forced closure, class editing or second repair. Maximum 32 provider attempts including
native retries under the operating contract. Calibration/source/settings/snapshot failure stops
admission; custody failure stops dependent work and withholds acceptance. Failed live
acceptance triggers an architecture checkpoint, not an automatic prompt-patching loop.

Q4a. scripts/run_class_authoring_acceptance.py:qualify_trial_graph is the single bounded
continuation gate, reusing effectiveness_custody.collect_slot and join_invocations,
benchmark_effectiveness.install_checks, and shared source/channel validation. Freeze
calibration files/observations, source/harness/settings and per-provider parent records.
Each parent must qualify before copying; require a durably registered blocking class
bound to the original Boolean-identity defect, retaining its actual definition, debt,
resolved evidence and an implementer assessment of Q1 compliance. A one-off, missing,
misbound or unfaithful target cannot qualify. This is evidence-bound adjudication,
not an independent human rating or lexical semantic-proof checker.

Q4b. Freeze two arm records per qualified parent: exact original snapshot/specification,
seed-state bytes/digest, provider/parent identity, calibrated repair bytes/head, source,
settings and round-2/3 requests. Before spend compare each initial fork with its parent;
bind each actual dispatch to that expected snapshot and exact predecessor state. Join
requests, native outputs/audits/channels and durable successor states. The target class
must remain unchanged through both corrections and cold finals; require its canonical
closure in both arms. Qualify correction before final admission and the complete graph
before Q4/Q5 acceptance. No class injection/edit, hint or extra call on nonqualification.

Q4c. Executable acceptance for qualify_trial_graph includes positive qualified replay and
negative controls for one-off-only success, substituted parent/fork seed, swapped arm
state/result, wrong repair head/changed snapshot, altered channel/cross-provider evidence,
missing audit and duplicate attempt. Include resealed mutations to exercise relational
joins rather than only outer hashes. Every rejection retains cost, stops dependent calls
and withholds acceptance. Frozen parent records never become mutable continuation state.

Q5. Update public guidance and AGENTS.md before review. After PLAN review, convergence
stays on CODE bound to this exact contract. Before merge/push require relevant tests,
qualified native acceptance and clear CODE convergence. Record source identity, production
diff size, largest modules, provider calls and elapsed time. Claim bounded correctness
improvement, not a population speed guarantee from this fixture.

## Next speed and architecture gate
S1. After Q1-Q5, rank current-source provider critical-path work from retained telemetry:
context preparation, repeated repository exploration, output, scheduling and retries.
Respect historical-version qualifications. Use prompt/schema/raw channels and call spans;
do not equate tokens or summed concurrent durations with elapsed savings. Existing
sub-6% local overhead is insufficient reason for another local-only optimization campaign.

S2. Select at most one materially promising scheduling/context/retry candidate, preserving
the operating contract, load-bearing context and evidence authority.
Before implementation or paid comparison, freeze its concrete change, representative
matched workload, sources/settings/order, all time/cost accounting, correctness controls
and qualification in a separate design card. Check the mechanism deterministically before
a bounded paired native comparison. Target at least 20% end-to-end time or cost reduction
with neither materially worse; no broad claim from one mode, a microbenchmark or favorable
subset. If no candidate warrants testing, publish the measured stop decision instead.

S3. Consider refactor/rearchitecture only for demonstrated root causes or bottlenecks.
Prefer one authoritative representation or simpler existing boundary over new subsystems.
Below the speed gate, demonstrated bug reduction or substantial maintenance/reasoning
simplification at high confidence can warrant a separately accepted design. Priority is
20%+ speed, bugs, maintainability, easier reasoning. No broad rewrite, provider/model/
effort downgrade, operating-contract weakening, new persistence or unsupported
quality claim. Issues #49/#50 are not automatically closed by this work.
