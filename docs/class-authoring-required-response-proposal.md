# Proposed acceptance change: test authoring independently of selection

Status: user approved. The executable obligations are now Q4f of
docs/class-authoring-quality-plan.md. PLAN review precedes implementation and the single
fresh campaign. The earlier task-only and ownership campaigns remain nonqualifying.

The current experiment asks for a reusable class, but still permits a one-off response.
Four retained campaigns cannot establish whether the candidate's authored classes accept
valid alternative repairs, because Codex has not authored a class. Its latest native
schema does admit new classes; neither transport nor missing member IDs explains the
remaining selection outcome.

Proposed bounded change: only in each acceptance parent process's initial consolidation
and its existing validation retry, project the production decision schema to require at
least one governing finding and allow only its existing new_class classification form.
Keep all remaining production fields, definition alternatives, bounds and local validators.
No invariant, procedure, predicate, member ID, severity, finding ID, evidence, or repair
syntax is supplied by the harness. The independent census lanes still detect the original
defects using ordinary production prompts and schemas. The test task explicitly requires
class authoring; it cannot stand in for evidence that a normal census selects classes.

The production runtime schema and classification policy stay unchanged. Correction and
cold final use their exact production prompts and schemas. Retain the existing explicit
authoring task, capture exact original/projected schemas and prompts, and join their full
digests to each native invocation. Prove projection identity outside the two stated schema
locations and prove that both initial and existing retry use the same restricted schema.
Do not add a call, retry, persistence mechanism, weaker parser or new public option.

Preserve the two independent defect gates, source/CLI/snapshot binding, calibration,
parent faithfulness assessment, exact copied states, both prescribed alternative repairs,
unchanged class definition and member inventory, correction-before-final admission,
both providers, serial nodes, 32-call ceiling and every existing resealed negative control.
Reject missing/altered projection, a task/schema on a lane or continuation, no target class,
wrong target evidence, or invented unsupported blockers. Terminal failure stops the affected
path; no unchanged rerun or manufactured parent state is permitted.

Before native spend, prove the restricted schema remains a subset of the production
schema using structural comparison and accepted/rejected concrete decisions, exercise the
full production-handler graph with its retry and existing negative controls, and review
the reopened design if the user approves it. Then freeze one fresh campaign. Retain all
earlier failures and all spent calls separately; never call them successful class samples.

If qualified, the resulting claim is narrowly honest: when explicitly tasked and required
to author a class, both native providers authored a faithful class that preserved closure
for both valid repairs. It does not prove ordinary class-selection reliability or general
latency improvement. The broader goal and later >=20% speed/cost gate remain intact.
